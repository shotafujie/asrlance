# 100発話・10構成の比較（2026-10-31）

既存50発話にKoepusの確認済みtest22件と、今回選んだ確認済み28件を加え、同じ100件を全10構成で新たに評価した。旧50件の測定値に追加分だけを足した集計ではない。以前の50件・72件の結果は別の測定として保持する。入力を保持していても再実行の出力が一致する保証はなく、実際にWhisperでは既存22件中の1件の編集数が前回と異なった。差を追加28件の構成効果だけで説明せず、今回の測定値をそのまま記録する。音声・正解文・個別の認識結果・個人パス・個別IDは公開しない。

## データを増やした範囲

| 区分 | 件数 | 音声時間 | 由来と確認根拠 |
|---|---:|---:|---|
| self_voice50 | 50 | 413.175秒 | 以前からの本人音声20＋30件。READMEに本人の参照確認記録があり、以前の入力hashと一致 |
| koepus_test | 22 | 63.168秒 | 既存のverified・test・speech・非空corrected_text。Asrivia由来の1セッション |
| koepus_added28 | 28 | 175.360秒 | 今回選んだverified speechペア。VoiceType由来の3セッション |
| 全体 | 100 | 651.703秒 | 元ファイルと参照版を固定したローカルmanifest |

追加分は全件投入せず、小規模な3セッションから29件の確認済み候補を選び、候補内の同文・近重複1件を除外した28件。15件が5秒超、10件が2〜5秒、3件が2秒以下、範囲1.216〜16.384秒。既存22件の短発話・単一セッションへの偏りを軽減するため、長めの発話を含む小規模セッションを中心に選んだ。モデルの認識結果・誤り率を見て選んだり、失敗例を差し替えたりしていない。長さとセッション由来に基づく選定であり、全用途を代表する無作為標本ではない。

レビュー状態は既存DBのverifiedと修正文を根拠にしており、今回新たな再聴取やラベル承認は行っていない。未確認・pseudo・却下・非発話・空の正解を追加の正解データとして使わない。参照本文の内容や切り出しの完全性を新たに認定したわけではない。追加28件のうち21件は元のASR下書きと同じ参照、7件は編集済み。下書きモデルは26件で未記録、2件でWhisper turboと記録されている。確認済み状態を尊重して採用したが、下書きへの依存やモデル寄りの表記の影響は排除できない。既存22件も18件が下書きと同じ、4件が編集済み。

## 学習との分離と重複

追加28件だけをtrainから抜くと同一セッションが学習と評価にまたがるため、元の3セッション全体83録音をtestへ予約した。評価に使ったのは28件だけで、残る55件は今回は使わない。55件には候補内の近重複として外した確認済み1件も含む。音声・参照・レビュー状態を保持し、変更は3セッションのsplitとその理由・更新日時のみ。変更前DB、元split、対象ID/hash、除外manifestを私的領域に保存した。

確認済み発話ペアの残量はtrain159→130件、dev1件は維持、test22→51件（この比較で使ったKoepusは50件）。未確認音声を今回のために承認していない。既存の学習用exportを実行した読取り確認で、予約3セッションの出力が0件であることを確認した。後日ラベル付けされる同一セッションの音声も今後の学習対象から外れる。

音声はSHA256による完全一致重複を、全100件および追加分と残存train/dev全種別の間で検査した。文字列はNFKC、空白・Unicode句読点/記号除去後の完全一致に加え、8文字以上・長さ比0.85以上・SequenceMatcher比0.90以上を近重複として検査。既存72件、追加候補内、残存train/devとの一致を調べた。残存の未確認発話はASR下書きでの予防的な照合なので、漏れを完全に保証するものではない。同じ内容の言い換えや再録音をすべて検出できるわけでもない。この重複検査の正規化は、後述するCER採点の正規化とは別である。

追加28件と残存train/devの検査では一致なし。一方、全100件へ検査を広げると、既存22件中の2件が残存trainの18録音（確認済み1件・確認待ち17件、6セッション）と同文/近重複候補になった。旧セットの比較を保持するため今回は既存2件を除かず、多数の追加セッション移動も行っていない。対象は私的な除外候補一覧に記録したが、6セッション全体は現行trainから予約除外していない。したがって全100件を今後のFTから独立した評価に使うには、この既存の重複候補を先に整理する必要がある。今回の比較はその独立性を主張しない。

既存の準備・学習曲線metadata19ファイルには対象セッションの音声hashが見つからなかったが、過去の全学習利用を網羅した記録ではない。過去のFT利用や公開モデルの訓練データとの独立性は証明しておらず、「未見の独立test」とは呼ばない。split変更は過去の利用を取り消さない。古いexportや別経路で学習する場合も、私的な除外manifestを適用する必要がある。

## 音声・モデル・採点条件

元の16kHz mono PCM16 WAVをコピーし、音声内容のhashを保持。再切り出し・結合・共通の音量調整・無音切除・追加VADは行わない。内部特徴抽出やpaddingは各モデルの通常実装に従うため、全モデルの内部前処理が同一という意味ではない。Kotobaは既存の15秒chunk指定を維持し、今回の最長発話はこの長さを超える。Nueは既存の入力全体処理を維持し、16秒超ではライブラリ上の注意対象になる。

8つの既存ASR構成とNemotron stock/MLX8の計10構成を、同じ順序・1件ずつ・一度のpassで実行。既存キャッシュと分離済み環境を使用し、新しいモデルのダウンロードは不要だった。モデルID/revision、依存version、精度、prompt条件を併記する。Gemmaだけは以前からの前置き・引用符等を除くclean_gemma_transcriptionを維持。他モデルに参照に合わせた辞書置換や句点補完を加えない。

Nemotron stockはBF16/MPS eager、as-spoken prompt。MLX8はaffine 8bit/group64、日本語prompt、2秒以下で既存の短発話promptを使用。この2構成は量子化だけの比較ではない。旧8構成の生成上限到達は直接観測していないためnullとする。Nemotronは256token上限到達時にその構成を不適格にする。空出力は除外せず採点し、欠落・打切り・例外がある構成は全件成功の比較に混ぜない。

CERは既存calculate_cerを使用。正解と認識文の半角/全角スペースのみを除き、文字単位の挿入・削除・置換数で計算する。句読点、漢字/仮名、数字等の表記差も誤りに含める。正解ファイルは従来どおり前後の空白をstripして読む。

- macro CER：各発話のCERを同じ重みで平均。短い正解に対する挿入が大きく効く。
- micro CER：全発話の編集数合計÷正解文字数合計。長い参照の寄与が大きい。
- 挿入が多いとCERは100%を超える。都合の悪い発話を除外しない。

全100、旧50、既存22、追加28をそれぞれ集計する。同一入力/scorer/runtime条件のhash、case対応、各行の文字数・音声長、CERと編集数の整合、再集計とsummaryの一致を検査する。

## 時間・メモリ

各モデルを逐次ロードし、1秒の合成ゼロ音声で2回暖機。ロードと暖機は別記録。処理時間にはファイル読込・前処理・生成・decode・GPU同期を含み、採点は除外する。起動からの総待ち時間や、ストリーミングの発話終了遅延ではない。OSキャッシュを消したcold測定ではなく、反復ランダム化した性能試験でもない。Nemotron stockの初回は57件で終了記録が途切れ、プロセス不在を確認した。途中結果を保存して採点対象外とし、この構成だけ別runで100件を再実行した。終了理由の確定ログはなく、ツール接続断と同時期だったという観測に留める。掲載する速度は成功runの値で、中断・再試行を含む作業全体の待ち時間ではない。

RTFは処理時間合計÷元音声時間。RSS/MPS driverの観測は100ms間隔で、瞬間的なピークを取り逃す可能性がある。MLXはallocator peakを使う。これらは異なる指標で、合算しない。共有モデルlease、空き16GiBとswap増分512MiBの停止条件を維持し、利用中の本番アプリを勝手に停止・変更しない。

## 検証と適用範囲

公開コードの入力・重複・長さ・集計・改変拒否テストと、既存Nemotron/Gemma整形の回帰を確認。私的データを使わない17テスト（追加の10 subtests）成功、最適化モードpython -Oでも集計検査3テスト成功。参照hash検査と集計検査をそれぞれ無効化した2つの変異を専用コピーのテストで検出。私的なセッション予約処理の適格性・文字重複・変更許可範囲3テストも成功。入力100件の読込と全1000レコードの集計整合を確認した。正式な共通品質ゲートはNOT_ADOPTEDであり、formal submit PASSを主張しない。

選んだ入力の構成と参照作成経緯で順位は変わる。この結果だけで一般的な日本語ASR性能や本番採用を断定しない。既存アプリの既定モデルを変更していない。issue #4はこの変更で自動closeしない。

## ローカル再現

この公開リポジトリに私的入力は含めない。元音声の提供なしに同じ数値を完全再現できるという意味ではなく、ローカル保管した固定manifestと同じ環境が必要。

```sh
python evaluation/evaluate.py MODEL_ALIAS --frozen "$PRIVATE_FROZEN100" --out "$PRIVATE_RESULTS/runs/MODEL_ALIAS" --lock "$SHARED_MODEL_LOCK"
python evaluation/summarize.py "$PRIVATE_RESULTS"
python -m unittest discover -s evaluation -p 'test_*.py' -v
```

MODEL_ALIASはmlx、qwen17b、qwen、kotoba、nue、granite、cohere、gemma、nemotron-mlx8、nemotron-stock。各構成に対応する既存venvで実行する。Nemotronのモデルパス環境変数は既存の[手順](nemotron-evaluation.md)に従う。入力と出力は私的ローカル領域に置き、既存runは上書きしない。音声はofflineで処理する。

manifest.jsonはstatus=FROZEN、counts={all:100,self_voice50:50,koepus_test:22,koepus_added28:28}、rowsにcase/cohort/file/samples/audio_sha256/reference_sha256を持つ。ファイルはdata/以下に置く。公開用読込器は音声形式、長さ、実hash、非空参照、相対ファイル名、同一音声hashの重複を検査する。実測に使ったローカル版とASR呼出し・採点・計時処理は同じで、公開版では入力検証を追加強化した。

summary/numeric/verified-summaryにはローカル追跡情報があるため、そのまま公開しない。公開はaggregate CSVと、許可項目だけ抽出したモデル条件・数値表に限定する。FT予約処理と元ID付きmanifestは私的な管理操作として保持し、この公開ツールが利用者のDBを変更することはない。
